## When to Use It
When the user asks to analyze, sort, or organize files from a folder (Desktop, Downloads...) into themed or topic-based folders (Documents), rather than sorting by file type.

## Steps
1. Plan the mission (more than two actions).
2. List the contents of the source folder and existing destination folders (Documents) to know the topics already in place.
3. Separate real documents from program shortcuts (.lnk, .bat, .exe) and system files (desktop.ini): these stay in place.
4. Read small text files (.txt, .md, short .docx) to understand their actual content: file names alone are not always sufficient.
5. Announce the sorting plan in one or two sentences: for each file, the target folder. Reuse existing folders first, create a new one only if none fits.
6. Wait for explicit user approval before moving anything.
7. Create new folders if needed, then move each file (move, never delete).
8. Verify: re-list the target folders and the source folder to confirm everything is in place.

## Pitfalls to Avoid
- Never move program shortcuts (.lnk, .bat, .exe) or desktop.ini: these are software access points, not documents.
- Never judge a document based on its name alone: read the content of small text files before suggesting a sort.
- Do not create a new folder if an existing one already fits.
- Never move without prior user approval.
- Never delete: sorting means moving.
- Never touch the Local Agent installation folder (forbidden).
